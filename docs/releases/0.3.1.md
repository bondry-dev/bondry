# Bondry v0.3.1

This patch release improves correctness, resource management, and performance
without adding or removing public APIs. Bondry remains a pre-alpha project.

## Fixes

- Negotiate HTTP over TLS and normalize IPv6 literals for TLS identity checks.
- Preserve query-only HTTP request targets, escaped paths, and escaped queries.
- Validate malformed Swift address evidence and replay-cleanup timestamps before
  indexing data or calling native code.
- Preserve remaining request deadlines across the Swift bridge, including
  deadlines below one second.
- Apply HEAD response limits to the body rather than the representation length.
- Bound the Swift TLS session cache while allowing borrowed and active sessions
  to finish their requests.
- Allow concurrent Unix socket reads and writes, and interrupt blocked I/O when
  the transport closes.
- Keep webhook traversal boundaries stable across reentrant insertion and
  concurrent schema migration.
- Validate and rebuild storage usage during migration, with transactional
  rollback for invalid source records.
- Retain successful expiration cleanup when delivery admission rejects a
  duplicate or reaches capacity.

## Performance and maintenance

- Compact chunked HTTP response buffers once per receive call. The 16 KiB receive
  microbenchmark reduced median parsing time by 25.7%; this is not an end-to-end
  throughput measurement. See [the parser measurements](../performance/http-parser.md).
- Replace retained-history quota scans with transactional usage counters and
  indexed expiration queries. Unknown-record traversal also avoids a startup
  scan. See [the storage measurements](../performance/store-admission.md).
- Add regression coverage for transfer cancellation, late FFI callbacks, storage
  corruption, concurrent migration, and bounded traversal work.
- Consolidate loopback test fixtures and bound listener readiness waits under
  failure, cancellation, and timeout.

## Database upgrade

Opening an existing SQLCipher store automatically migrates it to schema 8.
Back up the store before upgrading. Older binaries cannot open the upgraded
schema; rollback requires a compatible binary or the pre-upgrade backup.

Migration preserves stored records and initializes validated usage accounting.
The first expiration cleanup still scales with eligible expired records.
Webhook traversal excludes records inserted after its captured boundary, but
does not provide a snapshot of concurrent state changes.
